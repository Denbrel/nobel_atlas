# Обновление и эксплуатация

## Гарантии и границы

`updater.py` не требует сторонних библиотек: используются стандартные `urllib`, `sqlite3`, `json`. Он скачивает два официальных набора, проверяет их согласованность, строит временную базу в той же папке, проверяет `integrity_check` и внешние ключи, затем заменяет файл через `os.replace`. При повторении неизменившегося набора файл не переписывается. Временный сбой не превращается в успешное частичное обновление.

Идентификаторы устойчивы; при новой загрузке учитываются исправления старых данных. Это обновление снимка, а не накопление дублей. Полный снимок для примерно тысячи лауреатов проще и надёжнее, чем предположение, что меняются только последние годы. Новый неизвестный JSON-атрибут сохранится автоматически; структурно несовместимое изменение API остановит нормализацию и потребует адаптации кода.

Блокировка `.sqlite.lock` предотвращает два локальных обновления. GitHub Actions дополнительно использует `concurrency`. При аварийном завершении машины файл блокировки может остаться: перед ручным удалением убедитесь, что другого процесса обновления нет. Резервная копия `.bak` не коммитится. Восстановление — вернуть предыдущий `nobel_database.sqlite` из истории Git или резервной копии.

## Частые ситуации

| Ситуация | Действие |
|---|---|
| API вернул 429 / 5xx | Работают ограниченные повторы. При неуспехе база сохраняется, workflow красный. Повторите позже. |
| API просит `Retry-After` больше минуты | Задача завершается; не отправляет преждевременные повторные запросы. Запустите позже. |
| Два endpoint разошлись во время объявления | Подождите согласованного обновления источника и повторите запуск. |
| Число лауреатов или записей премий уменьшилось | Проверьте изменения в источнике. Только после проверки возможен `--allow-count-decrease`; workflow по умолчанию его не использует. |
| `git push` отклонён | Проверьте права Actions, правила ветки и конкурирующие коммиты. Повторите workflow с новой вершины ветки. Ошибка не скрывается под «нет изменений». |
| Временная база готова, но публикация в GitHub не удалась | Текущая версия сайта остаётся прежней. Запустите job повторно. |
| Старая схема БД | Запустите новый `python updater.py`. После успешной полной загрузки он заменит схему с резервной копией. Или используйте готовую новую базу. |
| Карта без контуров | Убедитесь, что `static/world_110m.json` загружен в репозиторий, static serving включён и URL `app/static/world_110m.json` доступен. |
| Фильтры дали пустую выборку | «Сбросить фильтры»; код не строит некорректный график из пустого набора. |
| У Peace/Literature нет связей миграции | Нормальная неполнота аффилиаций источника. Места церемоний не подставляются. |
| `NOBEL_USER_AGENT` отсутствует для Wikidata | Укажите название приложения и реальную ссылку на репозиторий или контакт. В GitHub workflow URL задан автоматически. |

В настройках уведомлений GitHub включите сообщения о неудачных workflow. Проверяйте состояние расписания после долгого простоя: в публичных репозиториях оно может отключиться через 60 дней отсутствия активности. Это ограничение платформы, а не ошибка импортера.

## Wikidata для автора проекта

`NOBEL_USER_AGENT` — переменная окружения процесса обновления. Это идентификация приложения перед Wikimedia, **не пароль и не настройка посетителя**. Указывать её в интерфейсе сайта или Streamlit Secrets для просмотра данных не требуется.

Проще всего открыть GitHub → Actions → **Update Nobel data** → **Run workflow** и включить `wikidata`. Workflow автоматически использует URL текущего репозитория.

Для ручного запуска из терминала в корне проекта:

```bash
# macOS / Linux
export NOBEL_USER_AGENT='NobelAtlas/2.2 (https://github.com/Denbrel/nobel_atlas)'
python updater.py --wikidata
```

```powershell
# Windows PowerShell
$env:NOBEL_USER_AGENT='NobelAtlas/2.2 (https://github.com/Denbrel/nobel_atlas)'
python updater.py --wikidata
```

Команда запишет обогащение в локальную SQLite. Чтобы сайт его увидел, обновлённую базу надо закоммитить в репозиторий; workflow делает это автоматически. Обычный `python updater.py` без Wikidata не требует этой переменной.

## Размещение и обновление кода

Корень репозитория должен содержать `app.py`, `nobel_database.sqlite`, папку `nobel` и `requirements.txt`. Рекомендуемая версия Cloud — Python 3.12. Служебная панель минимизирована через конфигурацию и CSS; ссылки и печать доступны в подвале. Селекторы CSS могут потребовать проверки при смене закреплённой версии Streamlit.

Обновляйте модули одним коммитом. После замены модулей выполните Reboot app, чтобы исключить использование прежних Python-классов в работающем процессе. Смена Python требует нового развёртывания, а не Reboot. Перед пересозданием сохраните настройки и secrets.

Проверки `scripts/check_deployment.py` и `scripts/smoke_http.py` помогают разделить ошибки Python, структуры проекта и выдачи файлов интерфейса. Если Cloud не доходит до запуска, нужен полный журнал установки, а не только сообщение о подготовке машины.

Colab-ноутбук использует отдельное окружение и управляемые процессы. `cloudflared` закреплён по версии и SHA-256; при смене версии обновляйте оба значения из официального релиза. Quick Tunnel временный; при отключении среды откройте новую ссылку после повторного запуска.

## Воспроизводимый импорт без сети

Полные исходные ответы уже находятся в `source_pages`. Их можно извлечь и повторить нормализацию:

```python
from pathlib import Path
import json
from nobel.storage import DatabaseRepository

folder = Path('snapshot')
folder.mkdir(exist_ok=True)
for endpoint, envelope in DatabaseRepository().raw_snapshot().items():
    (folder / f'{endpoint}.json').write_text(
        json.dumps(envelope, ensure_ascii=False), encoding='utf-8'
    )
```

```bash
python updater.py --snapshot-dir snapshot --db rebuilt.sqlite
```

Исходные JSON не теряют неизвестные поля. Если нужна история именно сырых ответов по датам, добавьте внешнее архивирование снимков; текущая база хранит последнюю установленную версию, история версий — в Git.

## Доступ API

По умолчанию API доступен только по локальному адресу при запуске из README. Для размещения на сервере настройте HTTPS на уровне платформы или reverse proxy; ограничьте число запросов на этом уровне. `NOBEL_API_KEY` — необязательная простая аутентификация для n8n, не полноценная система пользовательских аккаунтов. В репозитории нет секретов. Обновлять данные через публичный HTTP-запрос нельзя.
